## Start with a pilot

The best path is the simple one:

1. Run a small internal pilot with a few developers.
2. Validate performance, privacy expectations, and repo compatibility.
3. Expand usage once your team is comfortable with the workflow.

LocalCode is open source, so teams can evaluate the product directly before making a broader rollout decision.

## Privacy and data handling

LocalCode is designed for local-first use. In the standard setup:

- model execution happens on the developer's machine
- code and prompts stay on-device
- no API keys are required for the default local workflow

If your organization has stricter controls, LocalCode is a better fit for evaluation than cloud-first coding agents because the default posture is already local.

## Good fit for

- teams working with proprietary codebases
- security-conscious environments
- developers who want a terminal-first workflow
- organizations evaluating local AI before adopting hosted tools
