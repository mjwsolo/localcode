## Reproducing

```bash
# Clone the repo, install the venv (see CONTRIBUTING.md)
git clone https://github.com/<you>/localcode.git
cd localcode && uv pip install --python ./localcodevenv/bin/python -e .

# Run the full benchmark suite manually (you drive the TUI, harness times + verifies)
python eval/runner.py --all --model <your-model-tag> --mode manual

# Results land in eval/results/*.json — submit a PR adding your row to this page
```

When the headless mode lands (see `docs/HEADLESS.md` when it exists), you'll be able to run unattended:

```bash
python eval/runner.py --all --model qwen2.5-coder-32b-q4_k_m --mode headless
```

## How to read these numbers

- **Pass count** is the headline. 4/5 or better = the model is usable on this hardware. 3/5 or fewer = pick a smaller model or a bigger machine.
- **Median wall-clock** is the impatience test. If half the tasks took 10+ minutes, you'll find local agentic coding frustrating regardless of pass rate.
- **Average tok/s** sets the felt-speed of the TUI. Under 5 tok/s feels slow. Over 15 tok/s feels good. The token rate depends almost entirely on quant + hardware; the agent loop adds <5% overhead.
- **Rounds** = model→tool→model cycles. More than 15 rounds on a non-feature task often indicates the model is thrashing instead of making progress.
- **Notes** are where we capture what actually happened — the qualitative signal that explains the numbers. We try to be honest about failures, not just success.

## Contributing benchmark data

We want runs from as many machine + model combinations as possible. To submit:

1. Run `python eval/runner.py --all --model <your-tag>` (manual or headless)
2. The JSON files in `eval/results/` are your raw data
3. Add a row to the appropriate tier table above
4. Open a PR with the JSON files + table update
5. Brief notes welcome — what surprised you, what broke

We'll publish all submitted runs (including failures) — failures are signal too.
